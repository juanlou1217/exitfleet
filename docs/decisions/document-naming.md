# ADR：文档文件名不使用日期前缀

## 状态

- 状态：accepted
- 日期：2026-06-08

## 背景

早期文档使用 `YYYY-MM-DD-topic.md` 命名。这种命名会让文件路径随时间显得过时，也会让长期引用变得不稳定。ExitFleet 的功能方案、技术方案、测试记录和 ADR 会被反复引用，更适合使用稳定主题名。

## 决策

项目文档文件名不使用日期前缀，也不把日期放到文件名末尾。文件名使用小写英文主题名和连字符。

示例：

```text
docs/designs/release-distribution.md
docs/tests/test-gate.md
docs/decisions/document-naming.md
```

日期如有需要，只写在文档正文的元信息中。

## 后果

- 正面影响：文档路径稳定，引用更短，更适合长期维护。
- 负面影响：同一主题多次重大修订时，需要在正文中维护修订历史，而不是依赖文件名日期区分。
- 约束：如果同一主题需要多个版本，应使用清晰主题后缀，例如 `release-distribution-v2.md`，而不是日期。

## 替代方案

- 日期前缀：不采用，文件名噪音大。
- 主题名后加日期：不采用，仍然让路径随时间失去稳定性。
- ADR 编号：暂不采用；当前项目规模较小，语义文件名足够清楚。

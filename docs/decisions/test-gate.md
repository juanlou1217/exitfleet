# ADR：功能提交必须有对应测试并通过

## 状态

- 状态：accepted
- 日期：2026-06-08

## 背景

ExitFleet 会持续进行 AI 辅助开发。如果功能实现没有对应 Go 单元测试，或者测试没有执行通过就提交，后续重构会快速失去安全边界。项目需要明确 Go 单元测试位置和提交门禁。

## 决策

每次新增功能或修改行为必须同时维护：

- Go 单元测试：写在对应 Go package 同目录的 `*_test.go`。
- 测试记录：写在 `docs/tests/short-topic.md`，只用于记录计划、用例清单、命令、结果和风险。

提交前必须执行完整必需验证。除非用户明确批准临时例外，否则全部必需测试必须通过后才能提交。

## 后果

- 正面影响：每个功能都有可执行 Go 单元测试和可追踪测试记录。
- 负面影响：开发速度会变慢，尤其是涉及 Docker、OpenVPN 和代理集成时。
- 约束：没有 Go 工具链或 Docker 环境时，功能代码默认不能提交，只能提交文档或等待环境补齐。

## 替代方案

- 只写 `docs/tests/` 不写 Go 单元测试：不采用，无法自动防回归。
- 只写 Go 单元测试不写测试记录：不采用，无法追踪测试范围和未覆盖风险。
- 允许测试失败后提交：不采用，除非用户明确批准临时例外。

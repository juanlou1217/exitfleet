# ADR：UI 技术栈保持可演进

## 状态

- 状态：accepted
- 日期：2026-06-08

## 背景

ExitFleet 当前处于初始化阶段，管理后台还没有进入实际开发。早期文档中曾写明不默认引入 React、Next.js、Gin、Echo 等框架，但这种表述容易被理解成长期禁止，限制后续 UI 复杂度提升后的技术选择。

## 决策

项目不在 README 中列出“暂不默认引入”的框架清单。后续如果 UI 需要更复杂的交互，可以在技术方案评审后引入 React 在线包或完整构建链。

框架引入规则：

- 必须先在 `docs/designs/` 记录技术方案。
- 必须说明收益、代价、集成方式、测试策略和回滚方式。
- 必须同步更新 README、AGENTS 和相关测试记录。

## 后果

- 正面影响：后续 UI 技术栈不会被早期约束锁死。
- 负面影响：引入前端框架会增加依赖、构建、缓存和发布复杂度。
- 约束：不能在没有设计记录的情况下直接引入大型框架或在线包。

## 替代方案

- 长期禁止 React/Next.js：不采用，过早限制了管理后台的演进空间。
- 现在立即引入 React：不采用，当前还没有足够复杂的 UI 需求支撑。
